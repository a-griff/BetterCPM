## Common archive structure

Each archive has one top-level directory matching its filename stem. Use these
subdirectories where applicable: `images/`, `docs/`, `source/`, `host/`,
`licenses/`, `evidence/`. Place `README.txt`, `RELEASE.json` and `SHA256SUMS.txt`
at its top level. Templates below must be completed from verified artifacts;
never fill unknown commit/hash/result fields with guessed values.

`RELEASE.json` records the package ID/version, full accepted source commit,
release tag when assigned, platform, exact included artifact hashes, component
versions/revisions, source/build provenance, qualification evidence and remaining
limitations. Existing component and disk records remain authoritative; do not
replace their identities with a package-wide version number. Package names do
not authorize removal of `-dev` markings.

Every package checksum file covers all other regular files in that archive,
including its release record; it does not list itself. At release level publish
`BetterCPM-1.0-SHA256SUMS.txt` covering the six final ZIPs and
`BetterCPM-1.0-RELEASE.json`. The release index lists the same accepted commit,
asset names, hashes, sizes and evidence references. Neither checksum file nor
release index contains its own hash. Hash final bytes after archive construction.

Candidate assemblies use a distinct `candidates/<full-commit>/` output directory
and remain explicitly unaccepted. Preserve earlier generations and receipts.
Do not create or upload final-named release assets until acceptance is complete.

## System packages

System packages can be downloaded independently of Utilities. Supply the boot
and ordinary operating instructions locally; do not require the Documentation
ZIP to discover how to start. Explain where to obtain optional Utilities.

For the normal combined installation, A: is System, B: primary Utilities,
C: companion Utilities, D: work where applicable. With no Utilities installed,
B:/C: may hold compatible work media; instructions must not imply that tools
on those disks are part of the System ZIP.

The cpmsim package's `host/` contains the pinned lock, complete ordered patch
series, reconstruction builder, z80pack license and build/installation guide
from [CPMSIM-INSTALLATION.md](../platform/CPMSIM-INSTALLATION.md). Include the
matching pinned upstream source archive or an accompanying dependency-source
asset in the same release set, as specified by the source inventory. The runtime
profile needs patches 0001 and 0002; patch 0003 is qualification instrumentation.
If a host executable is included, label its OS/architecture, include its helpers
and environment.json, and qualify those exact bytes. Do not package an
unidentified installed cpmsim binary. Stock upstream cpmsim is insufficient.

The Model 4 instructions must cover the actual supplied image geometry,
emulator/hardware setup, writable copies, startup sequence and optional FreHD
clock support. The current test-disk guide is supporting historical material;
finish a release-specific fresh-install procedure before accepting this ZIP.

## Utilities package

Provide separate cpmsim and Model 4 downloads. Each contains only its matching
primary and companion images and their image-specific receipts/inventory. Use
`images/cpmsim/` in the cpmsim ZIP and `images/Model4/` in the Model 4 ZIP.
Preserve image filenames:

- `BetterCPM-Utilities-z80pack-332K.dsk`
- `BetterCPM-NOAH-z80pack-332K.dsk`
- `BetterCPM-Utilities-trs80gp-80T-DS-800K.dmk`
- `BetterCPM-NOAH-trs80gp-80T-DS-800K.dmk`

The historical NOAH companion name remains. It contains NOAH.COM, NOAH.OVL,
NOAH.TXT, PATCH.COM, PATCH.TXT, COMPARE.COM and COMPARE.TXT. CRCKSUM and MD5SUM
are on the primary images. Keep NOAH resident/overlay pairs matched. State
per-utility platform/service requirements; inclusion in this package is not a
claim that every utility runs on every CP/M implementation.

Preserve the existing Utilities builder's corresponding-source archives,
prepared native sources, provenance, permissions and attribution files in the
host package. The Utilities share one implementation, version and manual; splitting the host
archives does not fork their source or alter either disk. Both platform ZIPs
retain the required shared source/notice companions. These companions remain
a substantial part of download size; the split removes the other platform's
media, not those obligations.

A separate Source ZIP is an additional convenient download; it
does not authorize dropping source companions or notices selected by the
existing packaging specifications. Do not ship the internal builder's combined Utilities ZIP
as an unexplained nested archive; assemble its selected contents into this layout
and preserve their hashes and provenance.

## Source and documentation packages

The Source ZIP must reconstruct the accepted binaries and required patched
emulator from the documented pinned inputs. Include the build instructions and
full applicable third-party material; audit selected source closure against
component-input maps and build receipts. GitHub's automatic source download
is not assumed to contain external pinned sources or generated native companions.
Do not include stale build output, mutable developer images, caches or credentials.

The Documentation ZIP must provide a clear contents page distinguishing user
manuals, installation, programmer/architecture references and engineering history.
Include release notes, supported configurations, known limitations, disk inventory
and source/build guidance. Preserve editable sources. Include PDF editions only
after checking that they match the accepted manual source; existing PDF/DOCX
files do not automatically inherit subsequent Markdown corrections.

## Preparing review archives

Use a clean isolated checkout. `tools/prepare_release_systems.py` reuses the
existing source-snapshot build and filesystem validation to prepare both System
images. It boots only cpmsim. Model 4 is explicitly PENDING manual execution;
this path does not replace the fully boot-qualified distribution builder.

```sh
python3 tools/prepare_release_systems.py --output build/candidate-systems \
  --simulator /absolute/path/to/reconstructed/cpmsim
python3 tools/build_utilities_disk.py --build --output build/candidate-utilities
python3 tools/test_utilities_inventory.py --artifacts "$PWD" \
  --images build/candidate-utilities --output build/candidate-utilities-inventory.json
python3 tools/package_release_candidates.py \
  --cpmsim-system build/candidate-systems/z80pack \
  --model4-system build/candidate-systems/trs80gp \
  --utilities build/candidate-utilities \
  --inventory build/candidate-utilities-inventory.json \
  --upstream /path/to/pinned/z80pack/repository \
  --runtime-manifest /absolute/path/to/runtime/environment.json \
  --output build/release-downloads
```

Build the runtime with the matching source commit first, using the cpmsim
installation guide. All supplied System/Utilities/runtime receipts must identify
that exact commit. Use fresh output directories and retain failures. The packaging
tool only creates `-candidate.zip` names under `candidates/<full-commit>/`, with
PENDING gates and no accepted commit/tag. It has no publishing or final-promotion
mode. It reads archives back and verifies membership/bytes before recording
checksums. Model 4 preparation never invokes the blocked automated launch path.

The Source and cpmsim host kit carry SOURCE-IDENTITY.json and a pinned upstream
Git bundle. Their dependency README describes offline restoration. Source identity
is explicit when the BetterCP/M files were extracted without a .git directory;
an unrelated enclosing repository must not supply the identity.

Candidate Documentation uses current textual/editable references; older PDF/DOCX
editions are withheld until their contents are reconciled. System ZIPs also carry
their installation guide and User's Guide; Utilities carries its own manual.
